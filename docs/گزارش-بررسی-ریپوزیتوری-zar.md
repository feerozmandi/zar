## ۷. پیاده‌سازی الگوی شاخه‌بندی درخواستی (دستورهای دقیق)

### ۷-۱. ایجاد شاخه `dev` (در موتور محلی شما / یا توسط مالک)

```bash
# 1) اطمینان از همگام بودن local با remote
git checkout main
git pull origin main

# 2) ایجاد شاخه توسعه از main (پایه‌ی انشعاب توسعه‌دهندگان)
git checkout -b dev
git push -u origin dev
```

### ۷-۲. جریان کاری توصیه‌شده برای توسعه‌دهندگان

```bash
# هر توسعه‌دهنده از dev انشعاب می‌گیرد
git checkout -b feature/<نام-ویژگی> dev
# ... توسعه و تست ...
git add -A && git commit -m "feat: ..."
git push -u origin feature/<نام-ویژگی>
# سپس Pull Request: feature/<نام-ویژگی>  ➔  dev
```

### ۷-۳. انتقال نهایی به `main` (پس از تست/رفع خطا در dev)

```bash
git checkout dev
git pull origin dev
# تست نهایی و تأیید رفع خطاها (CI/بررسی)
git checkout main
git pull origin main
git merge --no-ff dev          # یا بهتر: PR: dev ➔ main
git push origin main
git tag v1.0.0                 # نسخه‌گذاری پس از تأیید نهایی
git push origin v1.0.0
```

> **قانون مهم (مطابق درخواست شما):** هیچ تغییری در `dev` (یا شاخه‌های feature) نباید قبل از دریافت آخرین تغییرات از شاخه‌ی والد خود (`main` → `dev` → `feature`) شروع شود؛ سپس هر توسعه فقط روی شاخه‌ی خودش پیش می‌رود و پس از تست نهایی از طریق Pull Request به والد ادغام می‌شود.
