## ۳) تأیید «آخرین تغییرات bill-analysis در ادغام نیست» — با شواهد

چکِ reachability با `git merge-base --is-ancestor`:

```
کامیت 8564b8d (HEAD of feat/bill-analysis-module)
  → در dev                       : ❌ نیست
  → در main                      : ❌ نیست
  → در arena/01a07d0d-zar        : ❌ نیست
  → در arena/01a07d41-zar        : ❌ نیست
```

لیست کامیت‌های شاخه که در dev نیستند:

```
8564b8d feat(api): ماژول تحلیل قبض برق با پردازش OCR و قوانین داخلی
```

و جست‌وجوی PR ها برای head این شاخه → **هیچ نتیجه‌ای** (نه باز، نه مرج‌شده).

### این کامیت چه چیزی اضافه می‌کند؟
```

apps/api/src/modules/bill/bill.controller.ts   (+42)   ← ماژول جدید bill
apps/api/src/modules/bill/bill.module.ts       (+12)

```

> نکته: dev فعلاً ماژول «audit» دارد (تحلیل قبض) اما هنوز ماژول `bill` (که این کامیت می‌سازد)
> را **ندارد**. بنابراین ادغام این کامیت تعارض‌ساز روی همان فایل‌ها نیست، فقط باید تصمیم بگیرید
> که رابطه/تفکیک `audit` (موجود) و `bill` (جدید) چیست تا دوباره‌کاری یا هم‌پوشانی پیش نیاید.

## ۴) اگر هر سه با هم ادغام شوند، کجا هم‌پوشانی/تعارض دارند؟

مقایسه‌ی مسیرهای تغییر یافته نسبت به `dev`:

| جفت شاخه | مسیرهای مشترک |
|---|---|
| engineering ∩ bill | `packages/shared/src/index.ts` |
| engineering ∩ solar | `packages/database/prisma/schema.prisma`، `packages/shared/src/index.ts` |
| bill ∩ solar | `packages/shared/src/index.ts` |

**نتیجه:** تنها نقطه‌ی هم‌پوشانیِ واقعی بین هر سه، فایلِ ریشه‌ایِ
`packages/shared/src/index.ts` است که هرکدام یک خط export جدید به آن اضافه کرده‌اند — این
تعارضی «متنی» و ساده است که با یک resolve دستی جمع می‌شود. در بقیه‌ی مسیرها سه ماژول مستقل‌اند و
ادغامشان تقریباً بدون تعارض خواهد بود.

## ۵) توصیه‌ی گام بعدی

1. **برای `feat/bill-analysis-module` یک PR به `dev` باز کنید** (این تنها چیزی است که کم دارد):
   ```
   gh pr create --base dev --head feat/bill-analysis-module \
     --title "feat(bill): ماژول تحلیل قبض برق (OCR + قوانین داخلی)"
   ```
2. PR های ماژولی را با ترتیبِ منظم در `dev` مرج کنید (engineering #28، solar #29 و سپس bill).
   در نقطه‌ی مرجِ `packages/shared/src/index.ts` (هر سه export اضافه می‌کنند) یک بار تعارض ساده
   resolve شود.
3. سپس در نوبت بعد، `dev → main` طبق خط‌مشی مخزن (main فقط نسخه‌ی پایدار).

> من در این مرحله **هیچ تغییری در مخزن اعمال نکردم** (فقط بررسی). اگر بخواهید PR شاخه‌ی
> `feat/bill-analysis-module` را همین‌جا باز کنم یا خودم سه شاخه را در dev ادغام و تعارض index.ts
> را برطرف کنم، بگویید.
