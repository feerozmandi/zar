# نوت ۶ — ماژول امکان‌سنجی نیروگاه خورشیدی

الگوی هدف: **Google Project Sunroof** (برآوردِ لحظه‌ای روی نقشه و سقف) + **EnergySage**
(مارکت‌پلیسِ مناقصه معکوس برای پیمانکاران). این سند، مبانیِ محاسباتی، ساختار داده،
سرویس‌ها و رابطِ کاربریِ پیاده‌سازی‌شده را توضیح می‌دهد تا توسعه‌ی بعدی روی آن سوار شود.

---

## ۱. اصلِ طراحی: یک منبعِ حقیقت

تمام فرمول‌ها در `packages/shared/src/solar/*` زندگی می‌کنند و هم در **سرور (API)** و هم در
**مرورگر (وب)** اجرا می‌شوند. نتیجه: عددی که کاربر در لحظه می‌بیند، دقیقاً همان عددی است که
در پایگاه‌داده ذخیره و در PDF چاپ می‌شود. هیچ ثابتی در UI یا کنترلر تکرار نشده است.

| ماژول | مسئولیت |
|---|---|
| `provinces.ts` | ۳۱ استان با کدِ استاندارد، نام فارسی/انگلیسی، مرکز، ارتفاع،alias |
| `sun.ts` | هندسه‌ی خورشید (میلِ Spencer)، طول روز، زاویه‌ی تابش، مدل آسمان صاف، انتقال HDKR، IAM |
| `climate.ts` | ۵۱ ایستگاه اقلیمی، درون‌یابی IDW، تصحیحِ ارتفاع، پروفایلِ تابش و دما |
| `shading.ts` | افقِ ناحیه‌ای (۳۶ بخش)، ضریب دید آسمان، دسترسی خورشیدی، گامِ ردیف |
| `roof.ts` | شبکه‌ی اشغال، چیدمانِ حریصانه، موانع، حریم، GCR، دسترسیِ پنل‌به‌پنل |
| `system.ts` | کاتالوگ ماژول/اینورتر، رشته‌بندیِ ولتاژی، تراز تلفات و PR |
| `production.ts` | شبیه‌سازِ ساعتی، قیچی‌شدنِ اینورتر، تطبیقِ تولید و بار |
| `tariff.ts` | تعرفه‌های ۱۴۰۴ (پلکانی، دیماند، آبونمان، فصلِ گرم) و سناریوهای ماده ۱۲/۱۶ و بورس سبز |
| `cost.ts` | پله‌های سرمایه‌ای، تفکیکِ هزینه، بهره‌برداری، تعویض اینورتر |
| `roi.ts` | جریان نقدی ۲۰ ساله، NPV/IRR/MIRR/LCOE، دوره بازگشت، تحلیل حساسیت |
| `epc.ts` | نرمال‌سازی و امتیازدهیِ پیشنهادها، خلاصه‌ی ناشناسِ پروژه |
| `report.ts` | ارکستراتور: ورودی → منبع → سقف → طراحی → تولید → قبض → سناریوها → ریسک‌ها |

**قراردادِ تقویمی:** تمام آرایه‌های ماهانه با ماه‌های **شمسی** و از **فروردین** شروع می‌شوند.
`MONTH_REPRESENTATIVE_DOY` و `MONTH_DAYS` در `sun.ts` مرجع هستند.

## ۲. زنجیره‌ی محاسبه

```
استان/مختصات ─► estimateSolarResource (IDW + ارتفاع + ساحلی)
                     │
سقف (مساحت یا چندضلعی + موانع)
                     │
                     ▼
              layoutArray ─► تعداد پنل، GCR، گام ردیف، دسترسیِ وزنی
                     │
                     ▼
            selectInverter + configureStrings ─► رشته‌بندی، DC/AC
                     │
                     ▼
     monthlyPoa (HDKR + IAM) ─► simulateProduction (ساعتی + دمای سلول + قیچی‌شدن)
                     │
                     ▼
        selfConsumptionSplit ─► قبضِ قبل/بعد (تعرفه) ─► سناریوها ─► جریان نقدی
```

### مفروضاتِ کلیدی (در گزارش به کاربر اعلام می‌شود)

1. **تابش:** میانگینِ GHI روزانه از ۵۱ ایستگاه با درون‌یابیِ عکسِ مجذورِ فاصله؛
   تصحیحِ ارتفاع و تعدیلِ دماییِ سواحل. کیفیت بر اساس فاصله از ایستگاه: high/medium/low.
2. **انتقال به صفحه:** مدل HDKR (Perez-simplified) با ضریبِ پراکندگیِ برآوردشده از
   شاخصِ صافیِ آسمان؛ ضریبِ زاویه‌ی تابش (IAM) برای بازتابِ پوشش شیشه.
3. **دما:** دمای سلول از NOCT با ضریبِ نصب؛ توان با ضریب دماییِ ماژول تصحیح می‌شود.
4. **تلفات:** غبار (متناسب با فاصله از آخرین بارش)، دما، ناهم‌خوانی، سیم‌کشی DC،
   راندمان اینورتر (منحنیِ بار + Euro-η)، قیچی‌شدن، ترانس/AC، در دسترس‌بودن.
5. **سایه:** افقِ ناحیه‌ای از موانعِ روی سقف و اطراف، سپس کاهشِ تابشِ پراکنده
   با ضریب دید آسمان و تلفاتِ ردیف‌به‌ردیف از گامِ بهینه.
6. **مالی:** افقِ ۲۰ سال، افتِ سالانه‌ی تولید، تورمِ تعرفه و هزینه‌ی بهره‌برداری،
   تعویض اینورتر در سال ۱۱، نرخ تنزیلِ پیش‌فرض ۲۳٪.

مقادیری که باید با داده‌ی واقعی جایگزین شوند (در مدلِ داده پیش‌بینی شده‌اند):
تابشِ اندازه‌گیری‌شده (`ClimateStation`), بنچمارکِ قیمت (`SolarCostBenchmark`),
نرخ‌های مصوب (`SolarPolicyPreset`).

## ۳. سناریوهای نظارتی

| سناریو | مبنا | سازوکار |
|---|---|---|
| `self-supply` | ماده ۱۶ (خودتأمین) | صرفه‌جویی از کاهشِ قبض؛ مازاد با نرخِ توافقی |
| `guaranteed-purchase` | ماده ۱۲ | فروشِ کل تولید با نرخِ مصوب (وابسته به ظرفیت) |
| `green-exchange` | بورس سبز | فروش در بازار با نرخِ روز + گواهیِ کربن |
| `hybrid` | ترکیبی | بخشی خودمصرفی، بخشی فروش |

موتور همه‌ی سناریوها را محاسبه و بهترین را بر اساس **NPV** پیشنهاد می‌کند و دلیل را
به فارسی توضیح می‌دهد (مثلاً «نرخِ خرید تضمینی برای این مقیاس از صرفه‌جوییِ مستقیم بیشتر است»).

## ۴. داده (Prisma / PostgreSQL)

نخستین مایگریشنِ مخزن در `packages/database/prisma/migrations/20260907000000_solar_feasibility`
تنها **جدول‌های جدید** می‌افزاید، بنابراین روی پایگاه‌داده‌ای که با `db push` ساخته شده هم امن است.

- مرجع: `climate_stations`، `solar_cost_benchmarks`، `solar_policy_presets`
- ارزیابی: `solar_roof_planes`، `solar_designs`، `solar_production_profiles`، `solar_scenarios`
- مارکت‌پلیس: `epc_bids`

> **نکته‌ی عملیاتی:** پوشه‌ی `src/generated` کامیت نمی‌شود؛ پس از اعمالِ مایگریشن،
> `pnpm db:generate` اجرا شود تا کلاینت با مدل‌های جدید بازتولید گردد. تا پیش از آن،
> سرویس گزارشِ کامل را در ستونِ JSONِ `solar_assessments.outputs` ذخیره می‌کند؛
> با بازتولیدِ کلاینت، نوشتنِ رابطه‌ایِ جزئیات (طراحی/تولید/سناریوها/پیشنهادها) فعال می‌شود.

## ۵. API (نسخه‌ی ۱)

| مسیر | توضیح |
|---|---|
| `POST /solar/feasibility` | گزارش کامل + ذخیره‌ی سایت، ارزیابی و سناریوی برتر |
| `POST /solar/assess` | مسیرِ سازگار با نسل قبل (ورودی قدیمی → مدل دقیق) |
| `GET /solar/assessments/:id` | بازخوانیِ گزارشِ ذخیره‌شده |
| `GET /solar/resource` | برآوردِ منبع تابش بر اساس استان یا مختصات |
| `POST /solar/design` | پیش‌نمایشِ چیدمان روی یک صفحه‌ی سقف |
| `POST /solar/roi-calculator` | ماشین‌حسابِ مالیِ ساده |
| `POST /solar/epc-request` | ثبتِ درخواستِ ارجاع به پیمانکاران |
| `POST /solar/epc-bids/compare` | رتبه‌بندیِ وزن‌دارِ پیشنهادها |
| `GET /solar/catalog` | کاتالوگِ تجهیزات، سناریوها و استان‌ها |
| `GET /solar/sites` | تاریخچه‌ی سایت‌های کاربر |

اعتبارسنجی با zod در `packages/shared/src/schemas/solar.ts` (استان با alias، چندضلعیِ سقف،
موانع، سناریوها، پیشنهادها).

## ۶. رابط کاربری (وب)

| صفحه | تجربه |
|---|---|
| `/solar` | برآوردِ لحظه‌ای: با هر تغییر، گزارش در مرورگر بازسازی می‌شود |
| `/solar/map` | نقشه‌ی تابش روی مرزِ واقعی استان‌ها (GeoJSON/OSM) + انتخاب و برآورد |
| `/solar/roof-designer` | ترسیمِ چندضلعی و موانع روی شبکه‌ی متری + چیدمانِ زنده |
| `/solar/feasibility-report` | طرح توجیهی: نمودارها، سناریوها، حساسیت، ریسک‌ها، چاپ/PDF |
| `/solar/marketplace` | مقایسه‌ی پیشنهادهای پیمانکاران و ارسالِ ناشناسِ پروژه |

پیش‌نویسِ پروژه بین صفحات با `useSyncExternalStore` روی `sessionStorage` جابه‌جا می‌شود؛
بنابراین کاربرِ ناشناس هم کل مسیر را بدون ورود می‌بیند (رفتارِ Sunroof) و تنها برای
ذخیره در تاریخچه یا ارسال به EPC به حساب نیاز دارد.

منبعِ داده‌ی مرزی: `apps/web/public/data/iran-provinces.json` — مشتق از OpenStreetMap
(پروانه ODbL 1.0)، ساده‌شده با `scripts/build-geo-data.mjs`.

## ۷. نقشه‌ی راهِ نزدیک

1. **فعال‌سازیِ ذخیره‌سازیِ رابطه‌ای** پس از `pnpm db:generate` (طراحی، تولید، سناریوها، پیشنهادها).
2. **تغذیه‌ی داده‌ی واقعی:** بارگذاری ایستگاه‌های تابش‌سنجی سازمان انرژی‌های تجدیدپذیر (ساتبا)
   و نرخ‌های مصوب در جدول‌های مرجع، با اولویت بر برآوردِ داخلی.
3. **تصویربرداری از سقف:** استخراج خودکارِ چندضلعی و شیب از نقشه‌های هوایی/تصویر پهپاد
   (معادلِ مدل‌سازی سه‌بعدیِ Sunroof).
4. **قراردادِ الکترونیک EPC:** تبدیلِ پیشنهادِ برتر به قرارداد و پیگیریِ پیشرفت.
5. **مانیتورینگِ پس از احداث:** اتصالِ اینورترها و مقایسه‌ی تولیدِ واقعی با پیش‌بینی.
