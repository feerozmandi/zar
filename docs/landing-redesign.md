# بازطراحی وب‌سایت سازمانی زر نور نیرو یکتا

تاریخ: ۲۰۲۶-۰۹-۰۸

شاخه: `arena/01a0811c-zar`، منشعب از `dev`

## نتیجه بررسی نسخه پیشین

- محور روایت، ماژول‌ها و زیرساخت هوش مصنوعی بود، نه خدمات مشاوره، طراحی و اجرای شرکت.
- هدر برای موبایل ناوبری جایگزین نداشت؛ برخی مسیرهای حساب کاربری به صفحه‌های موجود اشاره نمی‌کردند.
- Three.js و ارائه‌دهنده‌های پنل در ریشه سایت بارگذاری می‌شدند، حتی برای بازدیدکننده ناشناس لندینگ.
- canonical ریشه به صفحه‌های فرزند ارث می‌رسید؛ sitemap مسیرهای ورود و پنل خصوصی را نیز فهرست می‌کرد.
- ادعاهای آماده‌بودن همه محاسبه‌گرها، PDF رسمی، رایگان‌بودن و انطباق صددرصدی با وضعیت واقعی قابلیت‌ها تطابق نداشت.
- فرم مشاوره پاسخ `{ id, status, createdAt }` را با اسکیمای ورودی فرم می‌خواند و شماره تماس خالی را با وجود اختیاری‌بودن رد می‌کرد.

## جهت طراحی و محتوا

رنگ زمینه روشن و گرم، سبز جنگلی و تأکید لیمویی؛ فضای خالی بیشتر، کارت‌های ساده، تایپوگرافی فارسی و تصاویر بزرگ مرتبط با انرژی. پوسته تیره نیز پشتیبانی می‌شود و انتخاب کاربر حفظ می‌شود.

ترتیب محتوای صفحه:

1. معرفی شرکت و پیشنهاد همکاری
2. حوزه‌های تخصصی و خدمات: خورشیدی، شبکه برق، برق صنعت و ساختمان
3. رویکرد و معرفی شرکت
4. جعبه‌ابزار Xennic با فیلتر وضعیت
5. پرسش‌های متداول
6. دعوت به مشاوره و فوتر سازمانی

داده‌های عمومی در `apps/web/src/lib/marketing-content.ts` متمرکزند. وضعیت ابزارها مطابق کد موجود تعریف شده است: افت ولتاژ قابل استفاده؛ تحلیل قبض و ارزیابی خورشیدی آزمایشی و نیازمند حساب؛ دانشنامه و سایر محاسبه‌گرها در حال تکمیل. آماده‌بودن رابط به معنی فعال‌بودن API در هر محیط استقرار نیست.

شماره تلفن، نشانی، آمار پروژه، نظر مشتری و سابقه تأییدنشده اضافه نشده است. منبع و ماهیت مفهومی تصاویر در `apps/web/public/images/landing/README.md` ثبت شده‌اند؛ این تصاویر نمونه‌کار شرکت معرفی نمی‌شوند.

## تصمیم‌های فنی

- صفحه اصلی و درباره شرکت استاتیک‌اند؛ فرم تماس موضوع را از پارامتر معتبر `topic` می‌گیرد.
- `MarketingImage` از اندازه‌های AVIF/WebP از پیش تولیدشده استفاده می‌کند: تولید پرهزینه AVIF در اولین درخواست حذف شده است. اندازه‌ها توسط `picture` انتخاب می‌شوند؛ تصویر اصلی preload و high-priority است، بقیه lazy هستند.
- ابزار بازتولید تصویر: `node scripts/optimize-landing-images.mjs`، با sharp همراه Next.js و بدون افزودن وابستگی اجرایی.
- یک فایل فونت متغیر محلی به جای چند وزن؛ نام فایل بدون کروشه مانع تفاوت URLهای preload/CSS و دانلود دوباره می‌شود. `display: optional` و fallback تنظیم‌شده جلوی جابه‌جایی متن روی اتصال کند را می‌گیرند. مجوز OFL همراه فایل است.
- WebGL فقط در مسیرهای فضای کاری به‌صورت lazy بارگذاری می‌شود؛ لندینگ canvas ندارد.
- React Query و Toaster به ارائه‌دهنده فضای کاری منتقل شدند. اعتبارسنجی نشست نیز فقط هنگام نیاز بارگذاری می‌شود؛ ثابت نقش‌ها از subpath مستقل `@xennic/shared/constants` می‌آید تا همه اسکیمای مشترک وارد بارگذاری اولیه نشوند.
- برای ناشناس‌های صفحات عمومی درخواست بی‌دلیل refresh ارسال نمی‌شود. اطلاعات محلی فقط نشانه تلاش برای بازیابی نشست است؛ مجوز دسترسی همچنان در API بررسی می‌شود.
- ناوبری موبایل مبتنی بر Radix Dialog: مدیریت فوکوس، Escape، بستن با انتخاب لینک و بازگشت فوکوس به دکمه منو. مسیرهای حساب به پنل‌های موجود متصل‌اند.
- FAQ با `details/summary` بومی حتی بدون JavaScript کار می‌کند. فیلترها `aria-pressed` و اعلام تعداد نتایج دارند. skip-link، نام‌گذاری فرم‌ها، فوکوس قابل رؤیت و reduced-motion رعایت شده‌اند.
- فرم مشاوره اعتبارسنجی فارسی، موضوع مرتبط با CTA، حذف شماره اختیاری خالی، قرارداد پاسخ مستقل، حفظ داده در خطا، امکان تلاش مجدد و انتقال فوکوس به تأیید موفقیت دارد.

## سئو و پیکربندی انتشار

- عنوان و توضیح فارسی، canonical مستقل برای خانه/درباره/تماس، Open Graph و Twitter با تصویر واقعی موجود در مخزن.
- JSON-LD برای Organization، WebSite، WebPage، فهرست خدمات و FAQ از همان محتوای قابل مشاهده؛ escaping امن تگ script.
- sitemap فقط سه صفحه عمومی را فهرست می‌کند؛ مسیرهای خصوصی و ورود در robots کنار گذاشته شده‌اند. صفحه‌های منتشرنشده و تاریخ آخرین تغییر مصنوعی اضافه نشده‌اند.
- مقدار `NEXT_PUBLIC_SITE_URL` **پیش از build** باید به دامنه نهایی HTTPS تغییر کند؛ مقدار پیش‌فرض localhost فقط برای توسعه است.
- آدرس مرورگر برای API همان `/api/proxy` است؛ `API_INTERNAL_URL` فقط آدرس داخلی سمت سرور است.
- CSP تولیدی اجازه eval ندارد. bootstrap درون‌خطی Next/next-themes برای صفحات استاتیک مجاز است؛ سیاست nonce در صورت نیاز باید همراه تصمیم معماری رندر پویا بررسی شود.
- `ARENA_PREVIEW=true` فقط برای build/اجرای پیش‌نمایش تعبیه‌شده است. در استقرار عادی false باشد تا SAMEORIGIN و frame-ancestors برقرار باشند. `*.e2b.app` در allowlist توسعه مجاز است.

## آزمون و بازبینی

دستورات قابل تکرار از ریشه مخزن:

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm --filter '@xennic/web^...' build
corepack pnpm --filter @xennic/web lint
corepack pnpm --filter @xennic/web typecheck
corepack pnpm --filter @xennic/web test
corepack pnpm --filter @xennic/shared lint
corepack pnpm --filter @xennic/shared typecheck
corepack pnpm --filter @xennic/shared test
corepack pnpm --filter @xennic/design-tokens lint
corepack pnpm exec eslint scripts/optimize-landing-images.mjs
corepack pnpm --filter @xennic/web build
```

آزمون‌های Vitest، فیلتر وضعیت، محتوای FAQ، canonical/schema/robots/sitemap، حضور تصاویر و فونت، اعتبارسنجی فرم، شماره اختیاری، پاسخ موفق API و حفظ ورودی هنگام خطا را پوشش می‌دهند.

بازبینی مرورگر با Chromium/Playwright و axe در عرض‌های ۳۲۰، ۳۷۵، ۳۹۰، ۷۶۸، ۱۰۲۴، ۱۴۴۰ و ۱۹۲۰ پیکسل انجام می‌شود؛ همچنین پوسته تیره، منوی موبایل، لینک‌های بخش‌ها، redirect ابزارهای محافظت‌شده و FAQ بدون JavaScript بررسی می‌شوند. تست موفقیت/خطای فرم از پاسخ شبکه شبیه‌سازی‌شده استفاده می‌کند و درخواست واقعی در پایگاه داده ثبت نمی‌کند.

> تست رابط کاربری و قرارداد فرم، جایگزین تست end-to-end با Core API، پایگاه داده و سرویس ایمیل واقعی نیست. پیش از انتشار عمومی باید ارسال واقعی درخواست و دریافت آن در سیستم شرکت نیز بررسی شود.

هشدار موجود build درباره نام قدیمی `middleware.ts` مربوط به مهاجرت عمومی Next.js است و در این تغییر با مسیرهای احراز هویت درگیر نشده‌ایم.

### نتایج ثبت‌شده در این محیط

- Build وب موفق؛ خانه و درباره شرکت به‌صورت استاتیک تولید شدند.
- lint و typecheck وب/مشترک، lint توکن‌ها و اسکریپت بهینه‌سازی موفق.
- ۱۹ تست وب و ۱۶ تست مشترک موفق (جمعاً ۳۵؛ شامل تست‌های موجود).
- بررسی Playwright/axe در هر هفت عرض، پوسته تیره و منوی موبایل: بدون overflow افقی و بدون تخلف گزارش‌شده در قواعد بررسی‌شده WCAG A/AA.
- بازیابی نشست و خروج حساب در دسکتاپ و موبایل با پاسخ شبکه شبیه‌سازی‌شده موفق.
- فرم: اعتبارسنجی، موضوع انتخاب‌شده از لینک، شماره اختیاری خالی، حفظ داده پس از خطا، تلاش مجدد و فوکوس موفقیت بررسی شد.
- بارگذاری اولیه لندینگ بدون canvas، بدون خطای runtime/CSP و بدون درخواست refresh برای ناشناس تأیید شد.
