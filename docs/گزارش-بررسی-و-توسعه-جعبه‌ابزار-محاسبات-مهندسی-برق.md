## ۱. بررسی کل پروژه

پروژه **zar (Xennic)** یک مونورپوی TypeScript با `pnpm workspaces` + `Turbo` است که بک‌اند
`NestJS 12 + Prisma 7 + PostgreSQL + Redis/BullMQ` و فرانت‌اند `Next.js 16 + React 19 + Tailwind 4`
را پوشش می‌دهد.

### ساختار سطح‌بالا

| مسیر | نقش |
|---|---|
| `apps/api` | سرویس Core API (NestJS, ESM) |
| `apps/web` | پلتفرم کاربری (Next.js) |
| `apps/ocr` | سرویس OCR قبض |
| `packages/shared` | منطق مشترک: schema های zod، فرمول‌های مهندسی/خورشیدی، ابزار فارسی |
| `packages/database` | Prisma schema + کلاینت تولیدشده |
| `packages/ui` / `design-tokens` | کامپوننت‌ها و توکن‌های طراحی |
| `docs/` | مستندات راهبردی و فنی (نوت‌های ۱ تا ۵) |

### ماژول‌های Core API (`apps/api/src/modules`)

- **auth / users / admin** — احراز هویت (JWT)، مدیریت کاربر و عملیات مدیریتی با **audit log**
- **audit** — تحلیل هوشمند قبض (OCR + قواعد تعرفه)
- **solar** — امکان‌سنجی نیروگاه خورشیدی و ROI
- **engineering** — جعبه‌ابزار محاسبات مهندسی برق (موضوع این توسعه)
- **wiki** — دانشنامه/مرجع قوانین (مبحث ۱۳، نشریه ۱۱۰، توانیر)
- **ai** — دروازه‌ی چندمدلی (System Level / BYOK)
- **contact / health** — فرم تماس و وضعیت سرویس

### نظم کد (مشاهدات)
- همه‌ی محاسبات و schema ها در `@xennic/shared` «تک‌منبع» هستند و هم Core API هم وب آن‌ها را مصرف
  می‌کنند — این مرز درست است و توسعه بر همین پایه انجام شد.
- هر محاسبه‌ی مهندسی در دیتابیس ثبت می‌شود تا «دفترچه محاسبات» (EngineeringCalculation) قابل
  استناد باشد.
- قرارداد کلاینت از طریق `zod` تعریف و در وب با `zodResolver` و در API با `ZodValidationPipe`
  اعمال می‌شود.

## ۲. معماری و ساختار کد

مهم‌ترین لایه برای این توسعه:

```
packages/shared/src/engineering/
├── _common.ts          ← توابع ریاضی پایه (round/clamp/tan...)
├── standards.ts        ← کتابخانه‌ی استانداردها + جداول رنج تجهیزات (جدید)
├── registry.ts         ← فهرست ابزارها و دسته‌بندی آن‌ها (جدید)
├── voltage-drop.ts     ← افت ولتاژ (ارتقا: پیوست استاندارد + مقطع)
├── cable-sizing.ts     ← سایزینگ کابل (ارتقا: رنج آمپریسیتی + استاندارد)
├── capacitor-bank.ts   ← بانک خازنی (ارتقا: پرچم آستانه‌ی جریمه + استاندارد)
├── generator.ts        ← انتخاب ژنراتور (ارتقا: سری ظرفیت + استاندارد)
├── demand.ts           ← بار و دیماند (جدید)
├── short-circuit.ts    ← اتصال کوتاه IEC 60909 (جدید)
├── transformer.ts      ← ترانسفورماتور IEC 60076 (جدید)
├── switchgear.ts       ← کلید/بریکر (جدید)
├── busbar.ts           ← سایزینگ شینه (جدید)
├── voltage-classes.ts  ← طبقه‌بندی ولتاژ و رنج تجهیز (جدید)
├── earthing.ts         ← ارت (جدید)
└── lighting.ts         ← روشنایی داخلی (جدید)
```

**اصل کلیدی:** هر تابع محاسبه، علاوه بر نتیجه‌ی عددی، یک فیلد `standards` (آرایه‌ای از نوع
`StandardNote`) برمی‌گرداند که همان «توضیح کوتاه استاندارد در انتهای محاسبه» درخواستی است؛
این فیلد در `EngineeringCalculation.outputs` (JSON) نیز ذخیره می‌شود تا در دفترچه/PDF قابل
استناد باشد.

## ۴. استراتژی توسعه

1. **متمرکزسازی مراجع:** ساخت لایه‌ی `standards.ts` (کاتالوگ استانداردهای ایرانی/بین‌المللی،
   سری ظرفیت‌های ترانسفورماتور/ژنراتور/خازن، سطوح ولتاژ و Um/BIL تجهیز، سطوح روشنایی، مقاومت خاک).
2. **ارتقای چهار ابزار موجود:** افزودن پیوست استاندارد و رنج/سری مرجع به نتایج بدون شکستن رفتار
   پیشین (تست‌ها حفظ شدند).
3. **افزودن ابزارهای جدید (مورد‌به‌مورد):** هر ابزار = یک ماژول pure در `@xennic/shared` با
   تابع محاسبه + تست + schema ورودی.
4. **اتصال به Core API:** هر ابزار یک endpoint با اعتبارسنجی zod دارد.
5. **مستندسازی** در همین فایل + فهرست ابزارها در وب.
6. **ثبت در دفترچه:** چهار ابزار پایه ثبت می‌شوند (مطابق enum فعلی دیتابیس)؛ ابزارهای جدید
   تا افزودن enum در مهاجرت بعدی، **محاسبه‌ی بی‌وضعیت** برمی‌گردانند (شرح در بخش ۹).

## ۵. ابزارها به‌صورت مورد‌به‌مورد

> نمادها: خروجی هر ابزار شامل `standards[]` است. در زیر برای هر ابزار «روش»، «پیوست استاندارد»
> و «رنج تجهیز» آمده است.

### ۵-۱ افت ولتاژ (Voltage Drop) — ارتقا یافته

- **روش:** تک‌فاز ΔV=2·I·L·(R·cosφ+X·sinφ) و سه‌فاز ΔV=√3·I·L·(R·cosφ+X·sinφ) با R=L/(σ·A)،
  σ مس=۵۶ و آلومینیوم=۳۴٫۵ m/Ω·mm².
- **پیوست استاندارد:**
  - **IEC 60364-5-52:** حد افت ولتاژ مجاز در تأسیسات فشار ضعیف (روشنایی ~۳٪ و مدارهای دیگر تا ~۵٪) را
    مشخص می‌کند.
  - **نشریه ۱۱۰:** سند مرجع ایران برای افت ولتاژ مجاز مدارهای تغذیه بر پایه‌ی جدول‌های فصل ۱۱.
- **رنج:** آستانه‌ی پیش‌فرض روشنایی ۳٪ و عمومی ۴٪ (قابل‌تغییر با پرچم `lightingCircuit`).

### ۵-۲ سایزینگ کابل (Cable Sizing) — ارتقا یافته

- **روش:** کوچک‌ترین مقطع از سری استاندارد که هم جریان (پس از ضرایب تصحیح دما/نصب) و هم افت
  ولتاژ مجاز را رعایت کند.
- **پیوست استاندارد:**
  - **IEC 60364-5-52 / IEC 60287:** جدول‌های آمپریسیتی و روش تصحیح برای دفن/هوا.
  - **نشریه ۱۱۰ / توانیر:** مقادیر دقیق‌تر برای شبکه‌ی ایران (جدول ۱۱-۲ تا ۱۱-۴).
- **رنج:** خروجی شامل `candidates` و `ampacityRanges` برای هر مقطع است تا ناظر بتواند رنج مجاز را
  بازبینی کند. مقادیر جدول داخلی **تقریبی** است و در مهندسی جزئی با نشریه باید هم‌سو شود.

### ۵-۳ بانک خازنی / اصلاح ضریب قدرت — ارتقا یافته

- **روش:** Q = P·(tanφ₁−tanφ₂)؛ پله‌بندی از سری استاندارد خازن.
- **پیوست استاندارد:**
  - **دستورالعمل توانیر:** نگه‌داشتن cosφ بین ۰٫۹ تا ۰٫۹۵ (جریمه زیر ۰٫۹).
  - **IEC 60831/60871:** سری توان و ولتاژ نامی خازن‌ها در دو سطح فشار ضعیف/قوی.
- **رنج:** پرچم `abovePenaltyThreshold` (آستانه‌ی ۰٫۹) و `availableStepSizes` (مرحله‌های kVAr).

### ۵-۴ انتخاب ژنراتور — ارتقا یافته

- **روش:** S = (P·DF)/(cosφ·η)·margin سپس گردشدن به سری ظرفیت استاندارد.
- **پیوست استاندارد:** **IEC 60034-1** (ماشین‌های دوّار: بازده/بارگذاری) + مبحث ۱۳/نشریه ۱۱۰.
- **رنج:** `availableSizesKva` (۲۰ تا ۱۰۰۰ kVA) و `loadFactor`.

### ۵-۵ محاسبه‌ی بار و دیماند (Demand) — جدید

- **روش:** برای هر بار `kw×ضریب تقاضا` و سپس اعمال ضریب هم‌زمانی؛ جریان معادل در ولتاژ داده‌شده.
- **پیوست استاندارد:** **مبحث ۱۳** (ضرایب تقاضای فیدرهای ساختمانی) و **IEEE Std 141** (طراحی توزیع صنعتی).
- **رنج:** ضرایب تقاضای دسته‌بندی (روشنایی ۱٫۰، پریز ۰٫۴، موتور ۰٫۷۵، ...).

### ۵-۶ جریان اتصال کوتاه (IEC 60909) — جدید

- **روش:** سطح اتصال کوتاه S″k=√3·U·I″k؛ پیک ip=κ·√2·I″k با
  κ=۱٫۰۲+۰٫۹۸·e^(−3·R/X).
- **پیوست استاندارد:**
  - **IEC 60909:** روش استاندارد محاسبه‌ی I″k و پیک.
  - **IEC 60947-2 / IEC 62271-100:** انتخاب قدرت قطع کلید.
- **رنج تجهیز:** `availableBreakingKA` — سری فشار ضعیف Icu و سری ولتاژ متوسط (۱۲٫۵ تا ۵۰ kA).

### ۵-۷ انتخاب ترانسفورماتور (IEC 60076) — جدید

- **روش:** S_required = دیماند/ضریب بارگیری؛ گرد به سری استاندارد؛ سپس جریان‌های نامی و برآورد
  جریان اتصال کوتاه سمت ثانویه I_sc≈I_n/(Uk%/100).
- **پیوست استاندارد:** **IEC 60076** (سری ظرفیت/امپدانس) + سطوح ولتاژ ایران.
- **رنج تجهیز:** `availableSizesKva` (۵۰ تا ۲۵۰۰ kVA)، Uk٪ برآوردی (۴٪ تا ۶٪).

### ۵-۸ انتخاب کلید/بریکر — جدید

- **روش:** جریان نامی = ۱٫۲۵×جریان بار گرد به سری استاندارد؛ قدرت قطع از سری متناسب با سطح
  اتصال کوتاه نقطه.
- **پیوست استاندارد:** **IEC 60947-2** (فشار ضعیف) / **IEC 62271-100** (ولتاژ متوسط/بالا) + توانیر.
- **رنج:** `BREAKER_RATED_CURRENT_A` (۶۳ تا ۴۰۰۰ A) و سری قدرت قطع برحسب سطح.

### ۵-۹ سایزینگ شینه (باس‌بار) — جدید

- **روش:** مساحت لازم A=I/J با J تراکم جریان مجاز (مس ~۱٫۸، آلومینیوم ~۱٫۲ A/mm² در هوا).
- **پیوست استاندارد:** **IEC 62271-200** (تابلوهای فشار متوسط) / نشریه ۱۱۰.
- **رنج:** سری مقاطع استاندارد شینه ۱۲۰ تا ۱۰۰۰ mm².

### ۵-۱۰ طبقه‌بندی ولتاژ و رنج تجهیز — جدید (ابزار مرجع)

- **روش:** برای سطح ولتاژ سیستم، Um و سطح عایقی (BIL/LIWL) تجهیز را برمی‌گرداند.
- **پیوست استاندارد:** **IEC 60038** (ولتاژهای استاندارد) و **IEC 62271-1** (جدول سطح عایقی).
- **رنج:** جدول کامل سطوح ولتاژ شبکه (فصل ۷).

### ۵-۱۱ مقاومت الکترود زمین — جدید

- **روش:** تک‌میله R=(ρ/(2πL))·[ln(8L/d)−1]؛ برای چند میله از ضریب کاهش.
- **پیوست استاندارد:** **IEEE Std 80** (پست‌ها)، **IEC 62305** (صاعقه)، **مبحث ۱۳**.
- **رنج:** `SOIL_RESISTIVITY` (باتلاق ۳۰ تا سنگ ۳۰۰۰ Ω·m) و هدف مقاومت پیش‌فرض ≤۱۰Ω.

### ۵-۱۲ روشنایی داخلی — جدید

- **روش:** روش لومن N=(E·A)/(Φ·UF·MF).
- **پیوست استاندارد:** **مبحث ۱۳** و **CIE S 008** برای سطوح روشنایی توصیه‌شده.
- **رنج:** جدول `LIGHTING_SPACES` (اداری ۵۰۰ lux، کلاس ۵۰۰، انبار ۲۰۰، ...).

## ۸. رابط API

همه در گروه `engineering` (مصرف پس از احراز هویت، API prefix: `api/v1`):

| Method | مسیر | ابزار |
|---|---|---|
| POST | `/engineering/voltage-drop` | افت ولتاژ (ثبت دفترچه) |
| POST | `/engineering/cable-sizing` | سایزینگ کابل (ثبت دفترچه) |
| POST | `/engineering/capacitor-bank` | بانک خازنی (ثبت دفترچه) |
| POST | `/engineering/generator-size` | ژنراتور (ثبت دفترچه) |
| POST | `/engineering/demand` | بار و دیماند |
| POST | `/engineering/short-circuit` | اتصال کوتاه |
| POST | `/engineering/transformer` | ترانسفورماتور |
| POST | `/engineering/switchgear` | کلید |
| POST | `/engineering/busbar` | شینه |
| POST | `/engineering/voltage-class` | طبقه‌بندی ولتاژ |
| POST | `/engineering/earthing` | ارت |
| POST | `/engineering/lighting` | روشنایی |
| GET | `/engineering/tools` | فهرست ابزارها و دسته‌ها |
| GET | `/engineering/standards` | کتابخانه‌ی استانداردها |
| GET | `/engineering/calculations` | تاریخچه‌ی دفترچه |
| POST | `/engineering/export-pdf` | صدور دفترچه PDF (صف) |

Schema ورودی همه در `packages/shared/src/schemas/engineering.ts` است.

## ۹. محدودیت‌ها و مسیر توسعه‌ی بعدی

- **ثبت دفترچه برای ابزارهای جدید:** ستون `tool` در `EngineeringCalculation` از نوع enum با چهار
  مقدار است. برای ثبت ابزارهای جدید باید enum و مهاجرت دیتابیس افزوده و کلاینت Prisma بازتولید
  شود. در این توسعه آن‌ها به‌صورت محاسبه‌ی بی‌وضعیت برگردانده می‌شوند (خودِ منطق و استانداردها کامل است).
- **فرم‌های تعاملی وب:** ابزار جدید در Core API آماده‌اند؛ رابط کاربری تعاملی آن‌ها از الگوی
  `VoltageDropTool` قابل پیاده‌سازی است (فعلاً در وب به شکل placeholder/API در دسترس‌اند).
- **نهایی‌سازی جداول:** مقادیر آمپریسیتی/عایقی/جریان باید با جدول‌های دقیق نشریه ۱۱۰ و کاتالوگ
  سازنده در فاز مهندسی جزئی تطبیق داده شود (این نکته در خروجی‌ها و همین سند قید شده).
- **کتابخانه‌ی استاندارد** به‌صورت مرکزی در `standards.ts` نگه‌داری می‌شود تا همه‌ی ابزارها یکسان
  به روز شوند.
