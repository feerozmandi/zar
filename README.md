## 🌟 معرفی پروژه

**Xennic** پلتفرم جامع انرژی، مهندسی برق و هوش مصنوعی شرکت زر نور نیرو یکتا است که با تلفیق سه الگوی موفق جهانی (ممیزی هوشمند قبض، امکان‌سنجی خورشیدی و جعبه‌ابزار محاسبات مهندسی برق) طراحی شده است:

| # | ماژول | شرح کوتاه |
|:-:|:---|:---|
| ۱ | **فعالیت و تحلیل هوشمند قبض** (Smart Energy Audit) | OCR و استخراج خودکار داده از قبض برق، کشف خطاهای تعرفه‌ای، جریمه راکتیو و دیماند + توصیه‌های هوش مصنوعی |
| ۲ | **امکان‌سنجی نیروگاه خورشیدی** (Solar ROI & Feasibility) | محاسبه تابش منطقه‌ای، ظرفیت پیشنهادی، برآورد احداث و بازگشت سرمایه (ماده ۱۲ و ۱۶، بورس سبز) |
| ۳ | **جعبه‌ابزار محاسبات مهندسی برق** (Engineering Suite) | افت ولتاژ، سایزینگ کابل، بانک خازنی، ژنراتور مطابق IEC و نشریه ۱۱۰ + خروجی PDF رسمی |
| ۴ | **دانشنامه و مرجع قوانین برق** (Wiki) | مقررات ملی ساختمان (مبحث ۱۳)، نشریه ۱۱۰ و آیین‌نامه‌های توانیر |

معماری هدفمند: **NestJS + Prisma + PostgreSQL + Redis/BullMQ** (بک‌اند) و **Next.js + TailwindCSS + Shadcn/ui** (فرانت‌اند) — طبق سند `docs/پلتفرم زننیک/نوت ۳- معماری فنی، تک‌استک و ساختار API.md`.

## 🌿 جریان کاری Git (خط‌مشی رسمی پروژه)

```text
main  ←──────── (فقط نسخه پایدار و تست‌شده) ──────────
 │                                                   ▲
 │               ┌── پس از QA نهایی ──┐                │
 │               │   PR: dev → main   │               │
 │               ▼                    │               │
dev  ←────── (شاخه یکپارچه‌سازی توسعه) ───────────────
 │
 ├── feature/*   → PR → dev
 ├── fix/*       → PR → dev
 └── docs/*      → PR → dev
```

### قوانین الزامی

1. **قبل از هر تغییر، ابتدا از شاخه والد به‌روزرسانی بگیرید:**
   ```bash
   git fetch origin
   git checkout dev && git pull origin dev
   git checkout -b feature/<نام-ویژگی> dev
   ```
2. **هیچ کامیت مستقیمی روی `main` و `dev` مجاز نیست؛ تمام تغییرات از طریق Pull Request وارد می‌شوند.**
3. پیام‌های کامیت قراردادی (Conventional Commits) — راهنمای کامل در `CONTRIBUTING.md`.
4. قبل از PR: به‌روزرسانی از `dev`، اجرای تست/بررسی، و اطمینان از نبود سکرت/فایل حساس.
5. انتقال به `main` فقط پس از تست نهایی، بازبینی و رفع خطاها؛ سپس برچسب نسخه (SemVer) و Release.

## 🏗️ ساختار فنی مخزن (مونورپو)

پروژه از گام اول به‌صورت **pnpm workspace + Turborepo** ساخته شده است؛ همه‌ی نسخه‌ی
کتابخانه‌ها در `pnpm-workspace.yaml` (Version Catalog) تعریف می‌شود و هیچ بخشی
نسخه‌ی خودش را نصب نمی‌کند.

```
zar/
├── apps/
│   ├── web/                # Next.js 16 App Router — لندینگ، پنل‌ها، دانشنامه (RTL)
│   ├── api/                # NestJS 12 — هسته‌ی API، صف‌ها، Swagger
│   └── ocr/                # FastAPI — سرویس استخراج داده از تصویر/PDF قبض
├── packages/
│   ├── shared/             # منطق مشترک: محاسبات، اسکیمای zod، فرمت فارسی، رمزنگاری
│   ├── database/           # Prisma 7 (schema، کلاینت، seed) — تنها دروازه‌ی دیتابیس
│   ├── ui/                 # کامپوننت‌های مشترک (Tailwind v4 + Radix)
│   ├── design-tokens/      # پالت و توکن‌های برند (نوت ۴) — منبع CSS و TS
│   ├── eslint-config/      # پیکربندی متمرکز lint
│   └── typescript-config/  # پیکربندی متمرکز TypeScript
├── infra/                  # Nginx، PostgreSQL، Cloudflare (رجوع: نوت ۵ §۱)
├── docs/                   # مستندات فنی و اسناد محصول (فارسی)
└── scripts/                # bootstrap (ساخت .env و کلیدها) و پل اجرای ocr
```

### شروع سریع

```bash
cp .env.example .env
pnpm setup            # ساخت فایل‌های .env بخش‌ها + تولید JWT_SECRET/ENCRYPTION_KEY
pnpm install
pnpm db:generate      # تولید کلاینت Prisma (نیازمند دسترسی به شبکه در اولین اجرا)
pnpm infra:up         # PostgreSQL و Redis با docker compose
pnpm dev              # اجرا هم‌زمان web، api و worker با Turborepo
```

### دستورات پرکاربرد ریشه

| دستور | کاربرد |
|:---|:---|
| `pnpm build` / `pnpm typecheck` / `pnpm lint` / `pnpm test` | اجرای گراف کامل با کش Turborepo |
| `pnpm verify` | format:check + lint + typecheck + test (درِ ورود PR) |
| `pnpm format` | یکدست‌سازی کد با Prettier |
| `pnpm db:migrate` / `pnpm db:seed` | مهاجرت و داده‌ی نمونه |
| `pnpm ocr:dev` / `pnpm ocr:test` | بخش پایتون (venv خودکار در `apps/ocr/.venv`) |
| `pnpm infra:up` / `pnpm infra:down` | زیرساخت کانتینری |
