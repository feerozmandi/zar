## 🌟 معرفی پلتفرم

**Xennic (زننیک)** سامانه جامع و نوآورانه شرکت **زر نور نیرو یکتا** است که با تلفیق الگوهای موفق بنچمارک‌های برتر جهانی (نظیر EnergyCAP, Schneider EcoStruxure, Google Sunroof و EnergySage) و بومی‌سازی دقیق آن بر اساس ساختار شبکه برق و تعرفه‌های توانیر در ایران پیاده‌سازی شده است.

این پلتفرم به صنایع، مجتمع‌های تجاری، مشاوران انرژی و مهندسان برق امکان می‌دهد هزینه‌های مصرف انرژی را پایش و بهینه‌سازی کرده، طرح‌های توجیهی نیروگاه‌های تجدیدپذیر (ماده ۱۲ و ماده ۱۶) را تدوین و از ابزارهای محاسباتی استاندارد بر پایه هوش مصنوعی استفاده کنند.

## 🛠️ معماری فنی و تک‌استک

- **بک‌اند هسته (Backend API):** NestJS (TypeScript) با معماری مدولار، اعتبارسنجی DTO، مستندات Swagger/OpenAPI و معماری لایه‌ای.
- **فرانت‌اند و پنل‌ها (Frontend Web):** Next.js (App Router, SSR/ISR) + React + TailwindCSS + کامپوننت‌های مدرن و راست‌به‌چپ (RTL).
- **پایگاه داده و لایه ORM:** PostgreSQL + Prisma ORM با مدل‌سازی جامع رابطه‌ای و تایپ‌سیف.
- **پردازش صف و کارهای ناهمگام:** Redis + BullMQ برای مدیریت وظایف پردازش تصویر OCR و تحلیل‌های سنگین هوش مصنوعی.
- **مدیریت مخزن کد (Monorepo):** pnpm Workspaces + Turborepo جهت اجرای بهینه و موازی تسک‌ها با کش هوشمند.
- **زیرساخت کانتینری و استقرار:** Docker Compose + Nginx Reverse Proxy برای استقرار کم‌هزینه و مقیاس‌پذیر.

## 🚀 راهنمای شروع سریع

### پیش‌نیازها
- **Node.js:** نگارش `20.x` یا بالاتر
- **pnpm:** نگارش `9.x` یا `11.x` (`corepack enable`)
- **Docker & Docker Compose** (جهت اجرای PostgreSQL و Redis)

### نصب و راه‌اندازی گام‌به‌گام

```bash
# ۱. کلون مخزن و ورود به پوشه
git clone https://github.com/feerozmandi/zar.git
cd zar

# ۲. فعال‌سازی pnpm و نصب وابستگی‌ها
corepack enable
pnpm install

# ۳. کپی فایل متغیرهای محیطی
cp .env.example .env

# ۴. اجرای پایگاه داده و ردیس با داکر
pnpm docker:up

# ۵. ساخت کلاینت Prisma
pnpm db:generate

# ۶. اجرای سرویس‌ها در حالت توسعه
pnpm dev
```

پس از اجرا:
- **وب‌سایت و پنل‌های کاربری:** `http://localhost:3000`
- **مستندات API (Swagger):** `http://localhost:4000/docs`

### دستورات کلیدی مدیریت پروژه

```bash
# بررسی کیفیت کد و لینت
pnpm lint

# بررسی دقیق تایپ‌های TypeScript
pnpm typecheck

# اجرای تست‌های واحد و یکپارچه‌سازی
pnpm test

# بیلد کامل تمام بسته‌ها و اپلیکیشن‌ها
pnpm build
```

## 🛡️ دروازه‌های پنج‌گانه کیفیت (QA Quality Gates)

تمام تغییرات ارسالی به مخزن موظف به عبور موفق از دروازه‌های ۵‌گانه کیفیت هستند:

1. **دروازه ۱ (Local & PR Rules):** رعایت الگوی کامیت قراردادی (`feat:`, `fix:`, `docs:`, ...) و رعایت خط‌مشی شاخه‌بندی.
2. **دروازه ۲ (CI Test Matrix):** موفقیت صددرصدی تسک‌های `lint`، `typecheck`، `test` و `build` در گیت‌هاب اکشنز.
3. **دروازه ۳ (Security & Secrets Scan):** ممیزی آسیب‌پذیری‌های امنیتی و اسکن جلوگیری از نشت کلیدها.
4. **دروازه ۴ (Code Review & CODEOWNERS):** بازبینی و تأیید کد توسط مسئولین مربوطه در `.github/CODEOWNERS`.
5. **دروازه ۵ (Semantic Release & Lean Main Policy):** نسخه‌بندی خودکار با برچسب‌های استاندارد (SemVer)، پالایش فایل‌های غیرضروری و سبک نگه‌داشتن شاخه اصلی (`main`)، به گونه‌ای که تنها کدهای پروداکشن، بسته‌های فعال و اسناد رسمی عمومی به `main` منتقل شوند.

جزئیات کامل را در [GITHUB_SETUP_GUIDE.md](GITHUB_SETUP_GUIDE.md) و [CONTRIBUTING.md](CONTRIBUTING.md) مطالعه کنید.

## 🌿 معماری راهبری، خط‌مشی گیت و مدیریت حجم شاخه main

```text
main (پایدار / فقط کدهای ضروری پروداکشن و اسناد عمومی انتشار)
  ▲
  │ (Release PR با ممیزی حجم فایل‌ها و Lean Main Filter)
  │
dev (شاخه یکپارچه‌سازی و توسعه مستمر تیم)
  ▲
  ├── feat/<نام-ویژگی>      ──► PR ──► dev
  ├── fix/<نام-باگ>           ──► PR ──► dev
  └── docs/<عنوان-مستند>      ──► PR ──► dev
```

- **قانون پالایش شاخه اصلی (Lean Main Policy):** در آخرین مرحله هر توسعه هنگام انتقال به `main`، فقط فایل‌های مهم و ضروری پروژه که برای استقرار و انتشار عمومی لازم است منتقل می‌شوند تا از افزایش غیرضروری حجم مخزن و انباشت فایل‌های بلااستفاده جلوگیری شود.
- کامیت مستقیم روی `main` و `dev` توسط قوانین **GitHub Ruleset** مسدود است.
- تمام ویژگی‌ها باید در شاخه‌های مجزا پیاده‌سازی شده و از طریق PR به شاخه `dev` ارسال شوند.

## 🔒 امنیت و حریم خصوصی

- **حفاظت از کلیدهای اختصاصی (BYOK):** کلیه کلیدهای API ارائه‌دهندگان هوش مصنوعی (OpenAI, Anthropic, Gemini) که توسط مهندسان در پنل ذخیره می‌شوند، با الگوریتم **AES-256-GCM** و با کلید امنیتی سرور رمزنگاری می‌گردند.
- **جداسازی داده‌ها:** داده‌های صنعتی قبوض و محاسبات فنی هر شرکت در لایه دیتابیس به صورت ایزوله نگهداری می‌شوند.
- گزارش مسائل امنیتی را مطابق با [SECURITY.md](SECURITY.md) ارسال فرمایید.
